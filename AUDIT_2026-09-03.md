# Momentum Lab bug and integrity audit — 2026-09-03

## Scope and conclusion

Baseline: [`a538d0725ea577b50766bfcacb7acc5af5aef10b`](https://github.com/nmj94/momentum-lab/commit/a538d0725ea577b50766bfcacb7acc5af5aef10b)
(v0.14.0; tree `166219ee57409d1d95e6e3c0fbedfdc13b5a79a7`). Fix version: **0.14.1**.

Reviewed the CLI/configuration boundary, Yahoo and offline data paths, strategy
and ML chronology, single-asset accounting/statistics, selection/sensitivity/
bootstrap boundaries, checkpoints and exports, research-access governance,
portfolio books and declared membership, reports, packaging and CI. The review
combined source inspection, independent reproductions, full offline regression,
frozen accounting oracles, dependency scanning and static security analysis.

No P0 issue was confirmed within this scope. The ten finding groups below were
fixed: six P1 research-integrity defects and four P2 precision, resilience or
validation/reproducibility defects. These are project triage priorities, not CVSS
ratings or a claim that every possible bug has been found.

## Findings and repairs

| ID | Priority | Confirmed behavior before the fix | Repair and regression evidence |
| --- | --- | --- | --- |
| A01 | P1 | `^GSPC` and `_GSPC`, or `EURUSD=X` and `EURUSD_X`, could share the same lossy cache filename and silently reuse another asset's prices. Invalid metadata could leave those prices usable. | Canonical uppercase, collision-free escaping including underscores; reject mismatched metadata together with the cache. Symbol-pair, lowercase-alias, malformed-metadata and ambiguous-legacy-cache tests. |
| A02 | P2 | Reading a CSV cache could change a binary64 value, e.g. `0.12345678901234566`, changing an otherwise identical data snapshot and breaking reproducible resume. | Use pandas' round-trip float parser; test exact frame and snapshot identity. |
| A03 | P1 | Constant-return and one-observation histories reported zero performance; successive returns below −100% could multiply into positive equity. Short samples could emit non-finite higher moments. Undefined Sharpe could become a valid zero-ranked score. | Preserve actual gain/loss/CAGR/drawdown, make bankruptcy absorbing, keep finite legacy ratio/moment sentinels, and exclude undefined Sharpe from selection/sensitivity. Reject non-real, non-finite and overflowing numerical inputs. |
| A04 | P1 | Parameter sensitivity always used closing prices, even when the selected search used next-open execution. The diagnostic could describe a different trading convention. | Forward and validate the selected execution-price column; test both direct sensitivity and its search integration. Existing execution lag and development-only bounds are unchanged. |
| A05 | P1 | Legacy resume could continue with a checkpoint but no original `run_config.json`, after only warning that compatibility could not be checked. | Require the original configuration and registry identity before any resume. Tests verify rejection before data access and preservation of existing artifacts. |
| A06 | P1 | Reusing an unregistered run ID overwrote the old configuration and archived only journals. Old summaries/reports/rankings could survive a failed or empty replacement and appear to belong to the new run. | Archive the complete known artifact set under a common timestamp/unique suffix before writing new configuration; checkpoint SQLite first and reject invalid/busy journals. Test preserved configuration, reports, journal contents, unrelated files and removal of stale current rankings. |
| A07 | P1 | Single-asset reveal caching selected the earliest claim ID, so an older claim completing later could replace a result that had already completed. | Pin the first completion transactionally using the existing unique observation key. Test reverse completion with identical timestamps, legacy replay/completion fallback, read-only status and invalid-summary rollback. Preserve registry schema, identity and all exposure records. |
| A08 | P2 | Atomic writers used only a PID in their temporary filename; two writers in one process could overwrite/remove the same staging file. | Use exclusively created same-directory temporary files, flush/fsync before replace, and clean up on failure. Concurrent-thread and injected write/replace-failure tests cover all six cache/search writer paths. This is single-file publication, not a directory transaction. |
| A09 | P2 | Duplicate JSON keys, NaN/Infinity, loosely typed controls, invalid volatility targets and some malformed daily data were accepted or failed late. Expected CLI input errors could display tracebacks. | Bound recipe files to 1 MiB, reject duplicate keys/non-finite numbers including exponent overflow, validate controls/rates/targets/tickers/session dates/volume, preserve exchange-local dates, and return CLI usage errors. Bound registry JSON objects to 4 MiB. |
| A10 | P2 | CI could silently update the dependency lock; the security policy still named the obsolete 0.5.x line. | Add `--locked` to CI environment/test commands and correct supported-version/install guidance. The lockfile's only change is the local project version; dependency selections were not refreshed. |

Primary executable evidence is in
[`tests/test_audit_regressions.py`](tests/test_audit_regressions.py) and
[`tests/test_governance.py`](tests/test_governance.py). Two obsolete expectations
in `tests/test_basic.py` now assert the corrected symbolic cache name and real

## Compatibility and recovery

- Package version is 0.14.1. Single-asset engine/checkpoint schema 5, base registry
  user-version 1, portfolio schemas and all existing frozen fixture bytes remain
  unchanged. Corrected edge-case metrics and next-open sensitivity results may
  intentionally differ from 0.14.0.
- Existing runs/studies lock source, version, environment and data. Keep their
  original environment to reproduce/resume them; use new runs/protocols with
  the upgrade. Do not remove provenance fields, reset the registry or copy
  selected checkpoint rows to make an incompatible resume succeed.
- Old ambiguous symbolic caches are **not** reinterpreted or deleted. They are
  ignored in favor of new unambiguous cache keys; a fresh download or a verified
  offline dataset is needed. Ordinary uppercase ticker filenames remain usable.
  Local Yahoo cache files are still convenience caches, not tamper-proof custody.
- Legacy unpinned reveal caches prefer the earliest recorded replay source,
  otherwise stored completion time/event order. The next write pins that choice;
  status readers do not write. Where the historical record did not reliably
  capture completion order, this patch cannot reconstruct proof of that order.
- Legacy rerun backups retain the known old artifacts together under `*.bak.*`
  filenames. Keep the entire set and original registry, not only a CSV. Individual
  files publish atomically; backup/publication is not a whole-run transaction.
  Multiple coordinators must not share a run ID or result directory concurrently.
- Zero-valued Sharpe/Sortino remain backward-compatible sentinels for constant or
  one-observation histories, not evidence of a measured risk-adjusted score.
  Search uses its ineligible sentinel instead; actual performance is retained.

## Remaining boundaries and next work

These are not claimed fixed by passing tests:

1. Membership/source declarations are user supplied, not independently verified
   point-in-time constituents or licensed-data certification. IPO gaps, delisting
   quotes, halts and liquidation payouts still require a separately designed data
   and accounting contract. Never invent prices to fill those gaps.
2. The single-asset weight-return model and the separate long-only shared-cash
   portfolio ledger have different accounting/financing conventions; passing
   both suites does not make them interchangeable or model brokerage execution.
3. Sealing is a local workflow boundary, not encrypted custody or proof that data
   has never been inspected elsewhere. Manual filesystem/database edits or
   separate registries can defeat that history. Do not share real secrets or
   private market data in bug reports.
4. Bootstrap diagnostics are conditional on a selected strategy and are not a
   complete correction for trying many rules. ML chronology and software
   regression tests are not investment-performance validation.
5. Prioritize whole-run ownership/locking and crash-recovery semantics next,
   followed by checksum-bound provider-cache snapshots and independently
   maintained dataset/membership benchmarks. Introduce accounting or data-schema
   migrations explicitly; do not silently rebaseline the existing references.

This was a source-level bug/integrity review with reproducible local and CI gates,
not an external penetration test, broker integration certification, or assurance
of profitable trading. See [GOVERNANCE.md](GOVERNANCE.md),
[DATASETS.md](DATASETS.md), [PORTFOLIOS.md](PORTFOLIOS.md) and
[PORTFOLIO_STUDIES.md](PORTFOLIO_STUDIES.md) for their full contracts.
